# Threadlift

Use the Threadlift helper for a requested Codex-to-T3 recovery. The user chooses chats and files in a system-browser picker; an independent worker finishes after T3 quits. Do not improvise SQL or rewrite Codex history.

1. Read the [Threadlift README](https://github.com/batmanscode/threadlift). Use a trusted checkout of this repository in a stable location such as `~/Library/Application Support/Threadlift/app`, outside temporary T3 worktrees. If absent, clone `https://github.com/batmanscode/threadlift.git` there as part of the authorized recovery. A copied skill alone does not contain the importer.
2. Find Node 24.10 or later. Check `node --version`; use an available compatible runtime or arrange the required setup under the user's existing permissions. No runtime dependency installation is needed for a release checkout.
3. Run the count-only `node <checkout>/bin/threadlift.mjs inspect` with the intended local Codex/T3 homes. The helper is tested with T3 0.1.12/0.1.13 and the default Codex instance using the same Codex home as the source. Show compatibility warnings for later versions; those are untested even when the database matches. Unknown database formats stop the import. Keep chat titles and contents in the browser; do not use `inspect --details` unless the user asks to share that metadata with the agent. Respect its refusals; do not bypass version checks or point at a remote/unrelated profile.
4. Run `node <checkout>/bin/threadlift.mjs open` using your supported background/long-running command facility. The picker server stays running until preparation hands off; retain its private link and return control to the user. Let it open the **system browser**, not T3's embedded browser, because the picker/progress page must survive T3 quitting. Keep the printed private link local. The user can review and select chats/files there; do not infer a particular chat from its title alone.
5. In the same handoff message, explain what to do after clicking Prepare: finish other T3 runs, quit T3 with Cmd+Q, then wait with the browser page open. The worker waits for T3's ownership lock, backs up, imports, verifies, and attempts to reopen T3. Do not force-quit processes or take over the worker's writes.
6. Before real work in T3, have the user check the expected chats, earlier/recent messages, uploads, selected generated-file links, project folders, and missing/skipped files in the browser receipt. Local file links are opt-in; recorded attachments start selected. Recovered generated-file links open files in the selected project folder, with copied files listed in the receipt. For multi-file HTML, use workspace recovery if it includes the whole page folder, or a ZIP, and check the rendered page. Selecting separate files can split their layout; internal HTML links are not verified. If the user returns for help, use `status --job <path>` to inspect the receipt. Distinguish verified history/files and session linkage from a tested live continuation. Explain that import preserves Codex originals, while continuing resumes the same Codex session and can change shared project files; removing T3 does not undo that work. If the user authorized a follow-up test, use a minimal harmless turn; otherwise let them choose whether to continue.

Existing/partial T3 imports are not overwritten. A stale physical folder path requires locating the current folder; a missing file is reported, not reconstructed. On failure, read `status --job <path>` and preserve the backup. Pre-commit failures leave the database unchanged. For an interrupted prepared job, `apply --job <path>` retries or verifies it without importing twice. Verification of an interrupted job stops if the imported data has since changed. An already verified job returns its original receipt without reimporting or rechecking the files. Never restore a backup over newer work or a running T3 profile.

Deleting a T3 chat does not clear its import ownership. For a requested clean start on a new installation with no T3-only work to keep, follow the README's reset guidance: identify T3-owned paths, preserve the Codex home, original uploads, and original project folders, and use a fresh scan and newly prepared job after the fresh T3 profile is initialized. Do not reset a profile as a routine import retry.
